# v11 paper/code alignment notes

This version keeps the proposed CR-Koopman-MPC structure intact, but fixes the closed-loop failure observed in `analysis_outputs_v10`: the robot left the robust safety margin and then the physical lane.

## What changed in the implementation

1. **Event trigger is still residual/safety/input/watchdog-based**, but the model-error threshold was reduced so the held plan is invalidated before lateral drift becomes large.
   - `sigma_max: 0.38`
   - `sigma_min: 0.03`
   - `N_max: 80` is a watchdog only and is reported separately from non-stale events.

2. **The CBF is still neural and is not removed.**
   The barrier remains
   
   \[
   h_\theta(x)=h_{\mathrm{prior}}(P_{cbf}x)-c\,\mathrm{softplus}(g_\theta(P_{cbf}x)),
   \]
   
   with `P_cbf x = [py, vy]`.  v11 uses a non-saturating quadratic lane prior by default:
   
   \[
   h_{\mathrm{prior}}(py,vy)=k_y(y_{lim}^2-p_y^2)-k_v(v_y/v_{lim})^2.
   \]
   
   This keeps the CBF corrective near and outside the lane boundary; the v10 saturating prior could become too flat far from the lane center.

3. **The robust safety margin remains local-gradient based**:
   
   \[
   \rho_k = \|\nabla h_\theta(x_k)\|\,(L_x\bar w_k+\epsilon_{rec}+\epsilon_{sens})+\rho_{lin}.
   \]
   
   The conformal residual used for this margin is projected onto the CBF coordinates `[py, vy]`.

4. **Soft CBF-QP slack is no longer allowed to silently violate safety.**
   The CBF-QP still has slack for feasibility, but v11 adds a pre-violation recovery guard when either
   
   \[
   h(x_k)-\rho_k \le \epsilon_{guard}
   \]
   
   or the look-ahead margin
   
   \[
   M_h = \min_j(h(\hat x_{k+j})-\rho_k)
   \]
   
   is close to zero.  This is logged as `safety_recovery`.  It does not delete the CBF; it prevents a soft-slack QP from executing unsafe controls.

5. **Look-ahead margin indexing was fixed.**
   v10 evaluated the first controls of the stored plan when checking future safety, instead of the remaining controls starting at the current plan age.  v11 evaluates the remaining plan.

6. **OSQP `user_limit` outputs are not trusted as valid safety-filter solutions.**
   Non-optimal safety-filter statuses now force the controller toward the recovery guard when the safety margin is low.

## Paper edits required

The paper should explicitly state the following, otherwise the theorem/implementation may appear mismatched:

- The conformal score used in the robust CBF margin is a projected physical residual on `[py, vy]`, not the full lifted-state residual.
- The event-trigger model error is a projected physical error over `[py, psi, vx, vy, r]`, not the raw lifted error.
- The watchdog condition `k-t_i >= N_max` is a safety/staleness condition and is reported separately from model/safety/input-triggered replans.
- The CBF is a prior-anchored neural CBF, not an unconstrained MLP barrier.
- Safety evaluation reports both `h<0` and physical lane violations `|py|>1.75`.
- v11 includes a soft-QP recovery guard for the case where the robust margin is already close to zero despite slack feasibility.
